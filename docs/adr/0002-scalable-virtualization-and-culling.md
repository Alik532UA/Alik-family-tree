# ADR 0002: Scalable Tree Virtualization, Viewport Bounding and Playwright E2E Quality Gates

## Контекст

Генеалогічне древо Alik Family Tree містить 183 вузли персон та 8 поколінь і спроєктоване під масштабування до тисяч персональних записів з різних родинних гілок. При зростанні графу рендеринг сотень або тисяч SVG-вузлів та DOM-карток одночасно може викликати надмірне навантаження на композитор браузера та падіння FPS при панорамуванні або зумуванні.
Крім того, для забезпечення відсутності регресій при змінах структури, розгортанні нових релізів та перемиканні тем необхідні наскрізні E2E тести та пре-коміт контроль якості.

## Рішення

1. **Браузерна віртуалізація рендерингу (CSS Containment & Content Visibility):**
   - Усі картки осіб (`.person-card-node`) ізольовані через `contain: layout style; content-visibility: auto; contain-intrinsic-size: 220px 84px;`.
   - Завдяки цьому рушій браузера (Blink/Gecko/WebKit) повністю опускає фази компонування та відмальовки для всіх карток поза активною зоною огляду.

2. **Математичний розрахунок зони видимості полотна (`treeViewport.svelte.ts`):**
   - Додано обчислюваний геттер `visibleBounds` (`minX`, `maxX`, `minY`, `maxY`) у системі координат дерева з урахуванням `scale`, `panX`, `panY`, `containerWidth`, `containerHeight`.
   - Метод `isCardInViewport(x, y, width, height, margin)` дозволяє програмно фільтрувати вузли та лінії для необмеженого горизонтального та вертикального масштабування родинного архіву.

3. **Playwright E2E тестування та Husky гейти:**
   - Впроваджено `playwright.config.ts` та тестовий набір `tests/tree.spec.ts`, що автоматично верифікують завантаження полотна, фільтрацію у каталозі персон, аналітику поколінь та перемикання кольорових схем.
   - Створено `.husky/pre-commit` хук та інтегровано крок `npm run test:e2e` у GitHub Actions CI пайплайн (`.github/workflows/deploy.yml`).
